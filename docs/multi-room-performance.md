# 多窗口性能、弹幕与音画同步（2026-10-02）

## 当前实施：三分钟内存回看与进度条优化

小马最终选择内存缓存，不实施磁盘持久缓存。恢复约三分钟滚动回看，刷新网页/房间、关闭房间或重启后重新积累；不额外录像、不二次编码、不新增并行媒体连接。此前持久缓存内容保留为方案分析。

- 回看范围随最新实际缓冲边界前移，最多显示 180 秒。FLV 物理缓冲超过约 185 秒触发清理，清理到约 180 秒，留小幅调度余量；浏览器配额及关键帧仍可能使实际范围更短。回看/暂停继续接收，不能按暂停的播放位置无限保留历史。
- 已核对精确锁定版本 mpegts.js 1.8.2 / flv.js 1.6.2 的内部清理实现。采用局部、可恢复且有结构校验的适配，将清理参考位置改为真实直播缓冲末端，复用库的异步移除队列；不改全局浏览器 API，不直接与库争抢 SourceBuffer.remove。适配仅在各自实例生命周期内有效，升级库需复测。暂停可保留当前画面，恢复时若位置过期，跳至最早可播放位置并提示。
- 收到浏览器缓冲配额不足事件时，逐步缩短该房间实际保留范围，等待库的移除及追加队列完成后恢复被暂停的接收；兼容回退也释放旧的进度检查定时器。缩短范围保持到该播放器重建，不能承诺高码率多开一定缓存满三分钟；最低约十秒仍无法恢复时释放播放器并保留手动重试。
- 直播进度条保持三分钟固定尺度，未缓存区域置暗，播放位置与缓冲区域分开显示。实际时间作为寻址依据，滑块图形在可见控制条内平滑更新；隐藏、缩略窗口和后台停止动画，不逐帧更新 React，也不在进度条动画中反复读取布局。
- 拖动期间冻结时间映射并只预览，松开时按最新可播范围实际寻址一次；移出后松开、取消、Esc、键盘和触屏需正确处理。返回直播直接跳至最新已缓存位置，沿用当前播放器连接。
- 时间轴状态留在播放控制组件，运行时上报只更新引用；文字低频更新，其他窗口不随进度球重渲染。保留 Worker、按房间弹幕选择及此前窗口交互。
- 验证有限 duration 的平台直播、空缓冲、真实被清理历史、拖动时缓冲增长、暂停过期、返回直播、直接文件进度、隐藏动画与多窗口，以及关闭后连接/Worker 释放。单元测试、lint、TypeScript、独立生产构建；不提交、不推送，不操作用户现有服务。

## 设计分析记录：恢复三分钟回看（现已实施）

小马要求恢复三分钟回看，同时改善缓冲分批增长导致进度球追赶、跳动的视觉问题。以下保留当时的设计分析，当前代码与验证结果以上节为准。

- MSE 内存回看仍适用于几分钟的即时回看，技术本身没有因早期项目使用而过时。新版 mpegts.js 的默认自动清理仍以 currentTime 为依据；暂停或回退后，它不等于“最新直播边界往前固定三分钟”。不能只把清理参数改成 180 秒便承诺严格三分钟窗口。
- 建议产品范围为最新收到的可播放直播位置往前三分钟，实际范围取决于关键帧、已收到数据和浏览器配额；持续接收时滚动淘汰旧内容，暂停/回看不停止接收。播放位置过期后，恢复时移到最早可播位置并提示，避免恢复后卡在已清理数据上。
- 时间上限之外还需控制总缓存字节占用。8 Mbps 流三分钟压缩媒体约 180 MB，六路约 1.08 GB；20 Mbps 流六路约 2.7 GB，尚未算播放器其他开销。不能把三分钟当作内存占用很小，容量不足时应缩短可回看范围并展示实际范围。
- 短回看可先使用现有 MSE 缓冲，以最小改动恢复；要严格独立于播放位置的淘汰、跨换流保留、跨刷新回看，应增加独立的压缩分片缓存，让直播接收/保存与 MSE 播放各自管理。MSE 只装载播放位置附近的媒体，分片层按时长及字节数淘汰；磁盘 OPFS/IndexedDB 适合更长时长及持久化，不必为三分钟立即引入整套录像层。
- 实现严格直播边界清理前，需核对公开接口：现有库没有直接暴露可任意调用的 SourceBuffer 清理接口；避免未经验证依赖私有成员或全局改写浏览器 API。若短期沿用库按播放位置清理，应明确其物理内存保留范围和暂停行为，不能把 UI 限制冒充缓存硬上限。
- 进度条显示与媒体接收解耦：实际已缓存区域准确呈现，播放位置平滑更新；拖动期间冻结拖动坐标，结束后重新检查真实可播范围；后台和隐藏控件停止动画，避免为多路窗口重新引入逐帧 React 更新。图形变平滑不改变媒体时间，不为掩盖不同步而自动换流或刷新。
- 三分钟缓存及进度条优化不能证明斗鱼音画不同步来自平台；源时间戳、转封装、硬件解码吞吐和浏览器呈现仍需区分。本轮多开优化的本地验证未复现用户长期观看的症状。

## 三至五分钟持久滚动缓存（设计分析，未实施，当前不采用）

小马希望把此前半小时方案缩短为三至五分钟：缓存独立保存到本地，网络断开、关闭房间或网页刷新不主动删除；重新打开同一直播间，直接用进度条访问已保存内容，并在继续接收直播时逐步替换较旧内容。此需求超出了现有 MSE 缓冲，不能只调整 180/300 秒参数。

### 保留与操作语义

- 建议按“已录制的有效媒体时长”保留三至五分钟，而不是按关闭后经过的墙钟时间过期。没有新内容写入时，旧缓存保留；新片段完整写入成功且超过时长/容量时，才淘汰最旧片段。该建议替代此前文档中关闭超过时间窗口就淘汰旧内容的策略，具体容量上限仍需实施时确定。
- 连续观看：接收并保存新片段，同时淘汰超限旧片段。回看：读取旧片段播放，直播接收仍继续，保持单个上游媒体连接。暂停：暂停播放，仍接收并缓存。关闭房间/网页：停止接收及读取，保留已完成的片段。刷新/重开：加载持久索引与现存片段，新的取流连接形成新会话段。
- 停止接收期间没有录到的数据不能回看。断流、换画质或时间戳重置形成带独立初始化信息的会话段；同一个房间进度条需呈现已缓存内容及断点，不能假装中间连续录制。若采取按有效媒体时长保留，较旧片段可能来自很久以前，界面需显示实际录制时间，不能把它误标为距直播三分钟。
- 当前正在读取的少量分片取得短期读取保护；先从可选时间轴移除过期片段，待读取完成再释放其物理存储。已读入 MSE 的当前播放片段不因磁盘淘汰立即失效；保护有界，暂停不能永久锁住整个旧缓存。播放位置过期后恢复到最早仍可播位置并提示。
- 刷新、断开或关闭不会主动清空缓存，但浏览器清理站点数据、用户清缓存、不同浏览器/站点端口以及存储配额仍是保留边界。总容量不足时需要明确淘汰策略，不能默默宣称每个房间都保证完整五分钟。

### 并发与存储方案

- 使用独立的压缩媒体小分片（约两至四秒，受关键帧和实际流格式影响）与初始化/关键帧/时间索引，不对一个不断增长的巨型文件同时任意写删读。片段完成前不可出现在可回看索引；完成后不可变，读者只读已提交片段。
- 新片段按序写入；完成提交后更新房间时间轴，再安排旧片段淘汰。刷新恰逢写入时，最多丢失尚未提交的尾片，启动需识别并回收不完整片段或孤立记录，不能损坏此前已经提交的内容。
- 优先考虑 Worker 中的 OPFS 分片文件与 IndexedDB 元数据，或媒体与索引一并放入 IndexedDB 的兼容实现。跨两种存储无法依赖单个原子事务，必须通过提交顺序和启动恢复保证一致性；也需防止同一站点多个页面同时写同一房间。
- 回放 MSE 仅装载播放位置附近的一小段；持久缓存保存压缩数据，不二次编码、不再开一路上游取流。存储时长三分钟和五分钟的架构难度相同，主要改变占用：8 Mbps 时分别约 180 MB、300 MB/房间，尚未算索引和播放器其他内存。
- 当前 mpegts.js 对外 PlayerEvents 不暴露 INIT_SEGMENT/MEDIA_SEGMENT；内部转封装层有对应事件。实现需选择并验证可维护的取流/转封装接入方式，不能未经验证访问私有成员或重写全局 SourceBuffer 来截取数据。
- 回看期间，播放器进度监控与直播接收健康监控应独立，旧内容暂停不等同于网络卡流；实时弹幕不得直接叠到历史画面冒充同步回放。此缓存不解决来源或呈现造成的音画不同步。

### 验证与工作量

属于播放器与存储层的中等偏大改动，缩短半小时到三分钟不会省去会话、关键帧、并发与异常恢复的主要工作。先验证一间斗鱼持续写入、任意可缓存位置回放、循环淘汰、暂停和返回直播，再验证断流/刷新/关房重开、写入中断、跨会话/画质变化、存储不足、多个页面与多房间性能。尚未编写持久缓存代码。

## 此前多开优化约定（回看关闭已由当前方案替代）

- 多窗口卡顿和斗鱼实时音画不同步为重点。小马已确认浏览器使用硬件解码；仍需处理转封装、媒体缓冲和页面脚本开销。
- 保留用户当前画质，不按窗口大小自动降档，不因聚焦、全屏或布局变化换流。回看功能暂时关闭：移除直播回看进度与跳转入口，直播不再为回看持续刷新界面；直接文件的正常播放进度保留。
- 新房间弹幕默认关闭。聚焦或全屏时临时开启目标房间弹幕，其他房间保持自身状态；退出恢复进入前状态。进入前已手动打开，退出仍打开；期间手动开关优先且保存。
- 持久化的是用户对该房间的弹幕选择，临时自动开启不写成用户选择。刷新网页、关闭再打开房间后按用户选择恢复；声音继续沿用每次载入静音的原规则。旧数据中没有明确手动选择的默认开启值需迁移为关闭，避免升级后全部连接弹幕。
- 聚焦与全屏直接切换同一房间时延续临时会话和主动调整结果；切换房间、关闭目标与退出模式正确释放临时连接。关闭弹幕时卸载显示层并立即关闭弹幕连接。
- 弹幕无消息/无活跃条目时不占用逐帧循环，尺寸由 ResizeObserver 更新，避免空队列读布局和多次逐条测量。
- 去除重复 playing 的状态/历史写入，播放器状态无变化时返回原 reducer 状态，减少运行状态变动引起的持久化。
- 独立对照验证支持 Worker 的 FLV 内核，保留超时、关闭立即取消、失败清理与不支持时回退。音视频时间戳校正与解码/呈现落后分别检查，不用正常观看中的定时刷新或无条件跳直播掩盖不同步。
- 所有变更先保留本地，不提交、不推送。

## 验证计划

- reducer 与持久化：默认关闭、手动开关、临时开启不保存、模式转换、调整音量不改变弹幕所有权、关闭/重开、迁移与分享导入。
- 弹幕调度：空闲无 rAF、消息唤醒、动画清理、拥挤/过期淘汰、字号/尺寸变化、销毁释放。
- 生产 Edge 页面：多房间无多余弹幕连接、聚焦/全屏退出与重载行为；暂停、音量、刷新、关闭、卡流恢复；直播没有回看入口，直接文件保留进度。
- FLV：实际 Worker 工作、关闭静默连接立即停止网络、超时与失败清理、不同浏览器能力回退；相同本地音视频样本多路持续播放，统计页面主线程、丢帧与呈现偏差。
- 单元测试、lint、TypeScript、独立生产构建；不操作小马现有服务。真实平台长时音画同步须区分实测与尚未验证的范围。

## 实施与结果

已实现弹幕默认关闭、按房间保存手动选择，以及聚焦／全屏的临时开启与恢复；声音和弹幕分别记录手动调整。设置可分别关闭这两项自动开启。旧存档没有手动选择标记的默认开启值迁移为关闭，旧版手动添加的弹幕列表仍保留。

弹幕队列为空时停止 rAF；尺寸由 ResizeObserver 缓存，最多每帧 8 条，批量插入、测量、动画，完成或卸载取消动画和释放节点。重复 playing 每个播放版本只更新一次历史；运行时状态无变化不派发，视频运行状态变化不再写存储。单个窗口更新时，通过稳定回调和 memo 避免其他窗口重新渲染。

直播回看入口与直播时间轴上报暂时关闭；直接文件保留正常进度。FLV 的历史缓冲超过约 20 秒清理至约 10 秒，实际区间仍受浏览器配额和关键帧影响。保留画质，不做自动换流、定时刷新、播放速度追赶或无条件跳转。

播放使用精确锁定的 mpegts.js 1.8.2，将取流和转封装移入 Worker，MSE 留在页面。曾实测 MSE Worker 模式，但关闭窗口时库会在 attachment 关闭后读 SourceBuffer.buffered 抛出异常，因此未采用该模式。不支持 Worker 或探测构造失败时回退 flv.js 1.6.2 和可即时取消的 HTTP 加载器。Worker 配置不包含无法 structured clone 的 customLoader 函数；Worker 路径以可播放缓冲进展监控首次 15 秒、接收后 30 秒无进展，主动暂停、后台、离线和足够前向缓存时不判定，失败释放连接并显示手动重试。此项是连接超时保护，设置中的卡流自动重连仍默认关闭。

65 项单元测试、lint、TypeScript 和独立生产构建通过；弹幕引擎测试覆盖空闲唤醒、批量测量、轨道隔离、过期淘汰、字体变化与销毁。Edge 生产页面验证了实际 Worker、真实二进制弹幕显示、默认零弹幕连接、聚焦／全屏恢复、期间手动开关、刷新后保存选择与声音静音、暂停、音量，以及关闭后全部 Worker 和媒体连接释放；静默 HTTP 连接关闭也即时释放，不支持 Worker 的浏览器能力模拟下实际 FLV 解码通过。

连接异常实测通过：首次无数据约 15.6 秒报错，收到可播放数据后停止推进约 30 秒报错，各自释放 HTTP 和 Worker，只显示一次错误；默认不开自动重连。生产页面通过同房间聚焦↔全屏、切换聚焦房间、刷新、全部关闭与撤销；布局变化不重新取流。直接 MP4 文件进度和跳转通过。原有交互回归覆盖长按关注/中止/键盘/撤销、R 与输入/设置隔离、未开播历史、头像中键、分享与 Fork 链接、正常播放不刷新、卡流重试间隔/三次上限/手动重试和明确下播停止；无未捕获异常。

### 同源六路对照
